## Логи

Начинайте с сервиса, которому принадлежит проблемное соединение:

```sh
docker compose ps
docker compose logs -f quasar-server
docker compose logs -f quasistreaming-gigam
```

Чтобы посмотреть полный запуск стека:

```sh
docker compose logs -f --tail=100
```

## Хранилище моделей

ASR- и TTS-модели могут занимать много места. Храните их вне Git, по возможности монтируйте каталоги только для чтения и проверяйте свободное место перед пересборкой. Не удаляйте кэш CUDA ASR во время работы сервиса.

## Секреты и сеть

Храните ключи LLM, пароли базы данных и TLS-материалы в неотслеживаемом `.env` или secret manager. Не вставляйте их в Compose-фрагменты, которые публикуются в issue. Внутренние сервисы должны использовать имена Compose и не должны быть открыты в интернет.

Если proxy перестал получать трафик Яндекса, сначала проверьте DNS, затем `YANDEX_UPSTREAM_URL`, а после этого listener Quasar. Актуальный список доменов находится в репозитории `https-proxy`.
