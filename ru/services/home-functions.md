`home-functions` подключает стек к Home Assistant: объекты с настроенной меткой (label) становятся функциями и состояниями для процессора. Доступные команды зависят от домена и возможностей объекта.

Сервис реализует [API function/state-сервера](processor/function-state-server-api.md), поэтому процессор подхватывает устройства вместе с остальными источниками функций и состояний.

Он держит живое WebSocket-соединение с Home Assistant, так что состояние устройств всегда актуально, а новые размеченные устройства подхватываются без перезапуска.

Исходный код: [`v3rt3p/home-functions`](https://github.com/v3rt3p/home-functions), текущая ветка `main`. В репозитории нет ветки `master`.

## Переменные среды

| Переменная | Обязательна | Значение по умолчанию / пример | Назначение |
| --- | --- | --- | --- |
| `HASS_BASE_URL` | Да | `http://192.168.1.50:8123` | Адрес Home Assistant, доступный из контейнера по HTTP и WebSocket. |
| `HASS_TOKEN` | Да | - | Токен долгого доступа Home Assistant. |
| `PORT` | Нет | `8080` | HTTP-порт сервера. |
| `CONFIG_PATH` | Нет | `config.yaml` | Путь к файлу конфигурации сервиса. |

## Compose

Добавьте сервис в существующий раздел `services` вашего `docker-compose.yml`:

```yaml
services:
  home-functions:
    build: https://github.com/v3rt3p/home-functions.git#main
    restart: unless-stopped
    environment:
      PORT: "8080"
      CONFIG_PATH: /app/config.yaml
      HASS_BASE_URL: ${HASS_BASE_URL:?Set HASS_BASE_URL in .env}
      HASS_TOKEN: ${HASS_TOKEN:?Set HASS_TOKEN in .env}
    volumes:
      - ./home-functions/config.yaml:/app/config.yaml:ro
```

В `.env` рядом с Compose-файлом задайте `HASS_BASE_URL` и `HASS_TOKEN`. До запуска создайте файл `./home-functions/config.yaml` по примеру в разделе «Конфигурация»: иначе Docker может создать на его месте каталог. Если исходники уже лежат в `./home-functions`, вместо Git URL можно использовать `build: ./home-functions`.

Добавьте следующие переменные в `environment` существующего сервиса `processor`, сохранив его остальные настройки. Процессор запрашивает эти адреса как есть, поэтому они должны включать пути `/functions` и `/state`:

```yaml
services:
  processor:
    environment:
      PROCESSOR_FUNCTION_SERVER_URLS: http://home-functions:8080/functions
      PROCESSOR_STATE_SERVER_URLS: http://home-functions:8080/state
```

Если эти переменные уже содержат другие серверы, допишите адрес `home-functions` через запятую без пробелов, а не заменяйте список. Одного добавления переменных в `.env` недостаточно: Compose должен передавать их в `environment` процессора. Оба сервиса должны находиться в общей Docker-сети; публиковать порт `home-functions` на хост не требуется.

Если Home Assistant работает на той же машине, используйте доступный из контейнера LAN-адрес хоста или адрес шлюза Docker. `http://172.17.0.1:8123` подходит только при таком адресе шлюза и доступности HA на этом интерфейсе. Внутри контейнера `localhost` указывает на сам контейнер.

## Подготовка Home Assistant

1. Создайте токен долгого доступа: профиль пользователя → **Безопасность** → **Токены долгого доступа** → **Создать токен**. Сохраните токен в `HASS_TOKEN`.
2. Создайте метку для голосовых устройств в Home Assistant (`/config/labels`). В `labels` конфигурации нужен её **ID**, а не отображаемое имя; для новой метки `Alice` это обычно `alice`.
3. Разметьте объекты: **Настройки → Устройства и службы → Объекты** (`/config/entities`) → откройте объект → включите метку.

Хорошие кандидаты: свет, выключатели, вентиляторы, климат, шторы, медиаплееры, чайники (water_heater), увлажнители, пылесосы, замки, сцены и скрипты. Read-only домены вроде `sensor` не экспортируются — размечать их смысла нет.

## Конфигурация

`config.yaml` — обязателен только список меток:

```yaml
labels:
  - alice
```

Экспортируются поддерживаемые объекты, на которых висит хотя бы одна из перечисленных меток. Метку нужно назначить именно объекту (entity): метки устройства (device) или зоны (area) не наследуются этим сервисом. Пустой список `labels` не экспортирует ничего.

Опциональные переопределения по `entity_id`:

```yaml
entities:
  light.lampa_1:
    description: Стеллаж          # отображаемое имя, задаёт и префикс функций
    slug: shelf                    # явный префикс вместо транслитерации
  media_player.tv:
    description: TV
    modes:
      source:                      # какой список переименовываем
        HDMI 1: [playstation, приставка]   # [основное имя, алиасы...]
        HDMI 2: computer
```

`modes` переименовывает «сырые» значения списков Home Assistant в говоримые имена. Ключ выбирает список: `color`, `effect`, `source`, `sound_mode`, `hvac_mode`, `preset_mode`, `fan_mode`, `swing_mode`, `option`, `operation_mode`, `fan_speed`, `tone`, `mode`. Переименование меняет только то, что видит модель — в Home Assistant уходит исходное значение.

Для понятного голосового имени используйте `description` или имя объекта в HA. Поле `names` в текущей реализации не добавляет алиасы к публикуемым функциям. Префиксы функций должны быть уникальными; при одинаковых именах задайте разные `slug`.

## Как это работает

- Устройства выбираются по меткам: повесили метку на объект — он появился у ассистента, сняли — исчез. Списки устройств вести не надо.
- Функции генерируются из домена объекта и его возможностей (`supported_features`): у лампы будут яркость, цвет и температура, у медиаплеера — громкость и источники, у климата — режимы.
- Имена транслитерируются в префиксы функций: `Люстра` → `lyustra`, `Вытяжка` → `vytyazhka`, `Стеллаж` → `stellazh`. Переопределяется через `description` или `slug`.
- У каждого устройства с включением/выключением есть функция `<префикс>_history(days)` — сколько раз включалось и суммарно сколько работало. «Сколько раз за неделю кипятился чайник?» — это оно.
- Текущее состояние каждого устройства (`current_<префикс>_state`) экспортируется как состояние с человекочитаемой сводкой: яркость, температура, громкость, текущий трек и так далее.

Для лампы с именем «Стеллаж» сгенерируются `set_stellazh_state`, `set_stellazh_brightness` и `stellazh_history`; функции цвета и цветовой температуры добавятся, если соответствующие режимы есть в `supported_color_modes`.

Процессор передаёт каталог функций и состояния LLM. При настроенной модели команды вроде «включи Стеллаж» не требуют добавления фраз в deterministic parser. `nlp-service` — необязательный shortcut; неизвестные ему команды переходят к LLM. При нескольких лампах лучше назвать нужную явно: привязки по комнате станции сервис не делает.

Ограничение текущего процессора: `RemoteFunctionServer.callFunction` не читает тело HTTP-ответа. Поэтому `home-functions` публикует функции истории и возвращает их результат, но processor пока не передаёт этот результат модели. Настройкой меток это не исправить.

Поддерживаются все домены устройств Home Assistant: light, switch, media_player, climate, fan, cover, lock, vacuum, humidifier, water_heater, select, number, scene, script, button, siren, alarm_control_panel, valve, lawn_mower — и generic-фолбэк (вкл/выкл) для всего остального с сервисами `turn_on`/`turn_off`.

## Проверка

```sh
docker compose config --quiet
docker compose up -d --build home-functions
docker compose up -d processor
docker compose logs home-functions
# Exposed 'fan.tz3000...' as 'vytyazhka' (2 functions)  — по строке на устройство

# список функций, из контейнера processor:
docker compose exec -T processor node -e 'fetch("http://home-functions:8080/functions").then(async r => { if (!r.ok) throw new Error(`HTTP ${r.status}`); console.log(Object.keys(await r.json())) }).catch(e => { console.error(e); process.exit(1) })'
```

`up -d processor` применяет изменённое окружение, пересоздавая контейнер при необходимости. Обычный `restart` новые переменные Compose не применяет. После проверки каталога произнесите команду с точным именем устройства и сопоставьте `docker compose logs --since 5m processor home-functions`: ожидаются выбранная функция в processor и `Called function` в home-functions. Проверьте также фактическое состояние в HA: запись о вызове сама по себе не подтверждает его успех.

## Если что-то не работает

- **Функций нет / пустой `/functions`** — на объектах не висит метка из `config.yaml`, либо список `labels` пустой. Смотрите строки `Exposed ...` в логах.
- **`401` от Home Assistant** — токен невалиден или отозван; создайте новый.
- **Не коннектится** — проверьте, что `HASS_BASE_URL` доступен из контейнера, HA слушает на указанном интерфейсе и соединение не блокируется сетевыми настройками.
- **У устройства нет истории** — проверьте recorder и период хранения в HA; если результат есть в home-functions, но не доходит до модели, см. ограничение процессора выше.
- **Ассистент говорит, что не может управлять устройствами, а `/functions` не пустой** — проверьте URL в окружении processor, ошибки загрузки каталога и настройки LLM. Возможен и закешированный старый ответ: `docker compose restart processor` сбрасывает кэш.
- **Колонка говорит «готово», но устройство не изменилось** — проверьте ошибки в логах home-functions и доступность объекта в HA. Текущий HTTP-клиент processor не проверяет статус ответа на вызов функции, поэтому подтверждение голосом не гарантирует успешного выполнения.
